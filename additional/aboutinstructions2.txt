# TASK: Refine the About Page Layout and Implement Expandable Sector Popups

Inspect the existing portfolio project and improve the About page so that it feels
clean, intentional, and professionally designed.

The current page has:
- A central dithered portrait.
- An orbital halo with eight interactive sectors.
- Sector labels and hover descriptions positioned around the portrait.
- A central information card containing my name, introduction, and sector buttons.
- Existing hover and click interactions.

The current result feels cluttered because the sector headings and descriptions
compete for attention, some text overlaps other elements, and the central information
card obscures too much of the portrait.

I want to preserve the existing concept while improving its execution.

IMPORTANT:
Do not replace the design with a generic portfolio template.
Do not remove the dithered portrait or orbital halo.
Do not change the overall visual identity.
Reuse the existing components, styles, assets, and interaction logic wherever possible.

This task involves layout refinement and interaction changes, not a complete redesign.

--------------------------------------------------
1. FIX THE VISUAL HIERARCHY
--------------------------------------------------

The visual hierarchy should be:

1. Central portrait.
2. Eight orbital sectors.
3. Sector labels and brief hover descriptions.
4. Central identity information.
5. Detailed content, visible only when a sector is opened.

The portrait should remain the main focal point.

The surrounding sectors should feel like an organized interface rather than eight
text blocks competing with the portrait.

Avoid unnecessary visual noise.

Preserve the existing dark background, monochrome portrait, subtle orange accents,
technical typography, and orbital aesthetic.

--------------------------------------------------
2. CLEAN UP THE ORBITAL SECTOR LABELS
--------------------------------------------------

There are eight sectors surrounding the portrait.

Currently, the sector headings and their descriptions occupy too much horizontal
space and sometimes overlap the portrait, halo, or other labels.

Refine their presentation.

Requirements:

- Maintain eight sectors.
- Preserve their existing numbering and content.
- Keep sector labels short and scannable.
- Use a consistent typographic hierarchy.
- Keep the descriptions substantially shorter than the headings.
- Ensure that labels do not overlap one another.
- Ensure that labels do not collide with the portrait or central card.
- Maintain consistent alignment and spacing between corresponding left and right
  sector elements.
- Keep the labels visually associated with their corresponding orbital sectors.
- Use the existing hover behavior to reveal additional information.

Use these short sector labels:

01 SYSTEMS
02 AI / ML
03 BUILDING
04 OWNERSHIP
05 ENGINEERING
06 MILESTONES
07 BEYOND CODE
08 CURIOSITY

Do not permanently display long headings such as
"01 // SYSTEMS — THINKING IN SYSTEMS".

The main visible label should communicate the category, not repeat its description.

If the current implementation supports an expanded hover state, show the longer
heading or a brief description only when the user hovers over the corresponding
sector.

Keep hover content to approximately one short line.

Do not introduce additional always-visible paragraphs around the portrait.

--------------------------------------------------
3. MAKE HOVER STATES LESS CLUTTERED
--------------------------------------------------

The existing hover interaction should remain.

When the user hovers over a sector:

- Highlight its corresponding orbital segment.
- Expand the sector label subtly.
- Reveal a short descriptive phrase.
- Keep the remaining sectors visually subdued but readable.
- Avoid shifting the positions of neighboring labels.
- Prevent the expanded label from colliding with other elements.

Use the existing animation and transition mechanisms.

Do not introduce exaggerated movement, bouncing, scaling, or additional decorative
effects.

The interface should feel precise and controlled.

When the pointer leaves a sector, restore its normal state smoothly.

Ensure that hovering over the sector label and hovering over its corresponding
orbital segment activate the same sector.

Refine its existing presentation.

--------------------------------------------------
5. CHANGE CLICK BEHAVIOR: OPEN A PROPER POPUP
--------------------------------------------------

This is a mandatory interaction change.

CURRENT BEHAVIOR:
Clicking a sector changes the content inside the central information card.

DESIRED BEHAVIOR:
Clicking a sector should open a dedicated popup or modal containing the detailed
information for that sector.

The central information card must not be repurposed to display the full sector
description.

The detailed content should appear in a separate foreground layer.

### Popup appearance

Create the popup using the existing design language:

- Dark, near-black background.
- Subtle transparency if appropriate.
- Thin, understated border.
- Existing typography.
- Restrained orange accents.
- Clear title and readable body text.
- A visible close control.
- Optional small sector number or category label.

The popup should feel like an expanded version of the selected sector, not an
unrelated generic dialog.

It should be large enough to read comfortably but should not occupy the entire
screen unnecessarily.

Use a responsive maximum width and appropriate internal padding.

Long content must remain readable without overflowing the viewport.

### Background treatment

When the popup opens:

1. Keep the existing About page in the background.
2. Apply a translucent dark overlay.
3. Blur the background moderately using a backdrop-blur effect.
4. Keep the portrait and orbital interface faintly visible through the overlay.
5. Make the popup the clear visual focal point.

The background should remain recognizable but should no longer compete with the
popup content.

Use a smooth, restrained entrance transition consistent with the existing site.

Avoid excessive blur that makes the page feel visually muddy.

### Popup content

Each sector should open its own corresponding content.

Use the detailed descriptions already provided in the About-section content data.

Do not replace them with generic text.

The popup should contain:

- Sector number and category.
- A clear title.
- The corresponding detailed description.
- Relevant achievements or structured details, where applicable.
- A close button.

Preserve any existing content structure that supports paragraphs, tags, or
achievement lists.

Do not introduce unnecessary images or decorative elements.

### Closing behavior

The popup must close when:

- The close button is clicked.
- The Escape key is pressed.
- The user clicks the backdrop outside the popup.

Clicking inside the popup must not close it.

Prevent clicks from propagating from the popup content to the backdrop.

When the popup closes, restore the About page to its previous state.

The selected sector may remain subtly highlighted until the user moves to another
sector or dismisses the interaction, provided this does not conflict with the
existing interaction model.

### Accessibility

Implement the popup as an accessible modal dialog.

Where appropriate:

- Give it an accessible title.
- Move keyboard focus into the dialog when it opens.
- Keep keyboard focus inside the dialog while it is open.
- Restore focus to the triggering sector when it closes.
- Support keyboard dismissal with Escape.
- Ensure the close control has an accessible label.
- Prevent interaction with background content while the modal is open.

Use the project's existing accessibility patterns or dialog library if one is
already available.

Do not install a new dependency unless necessary.
